# 층 7 실측 원장 — 서버 로컬 쓰기와 클라이언트 캐시

2026-08-16, macOS 26.6 클라이언트 + Samba 4.23.6 (Ubuntu 26.04 ARM64 게스트).
결론과 처방은 [failure-model.md 층 7](../failure-model.md), 결정 근거는
[decisions.md](../decisions.md). 이 문서는 측정 자체의 원장이다 — 프로토콜, 수치,
그리고 **기각된 가설**.

## 측정 규율

- 모든 클라이언트 측정은 임시 마운트(`mount_smbfs` 직접 호출)에서. 운영 마운트는
  판정·측정 어디에도 쓰지 않았다.
- 실험 트리는 게스트 로컬 경로에 두고 게스트가 ssh 로 쓴다(smbd 우회 = 층 7 의 자극).
  공유 루트에는 아무것도 추가하지 않았다 (층 6 봉쇄 조건).
- 매 측정 fresh mount 로 클라이언트 캐시 상태를 동일화. 서버 페이지 캐시는 사전 워밍.
- 판정 기준(게이트)은 측정 전에 확정. 대조는 A-B-B-A 교차.
- t0 는 게스트 쓰기 ssh 반환 직후의 맥 시계 — 게스트·맥 시계 동기에 의존하지 않고,
  오차는 측정값을 보수적으로(크게) 만드는 방향.

## 재현 프로토콜과 수치

자극: 게스트 로컬 쓰기 (`printf > file` via ssh). 관측: 맥에서 새 값이 처음 보이는
시각. 폴링 0.5s, 셀별 상한 명시.

기본 셀 (마운트 옵션 없음):

| 셀 | 조건 | 결과 |
|---|---|---|
| C | 읽은 적 없는 파일 (대조군) | 0.016s |
| D | 디렉터리 hot, 새 엔트리를 `ls` 폴링 | 0.009~0.013s |
| H | 소파일(9B) hot, `cat` 폴링 | 1.12~1.68s (5/5) |
| S | 크기 변화를 `stat` 폴링 | 2.18s |
| L | 4MB hot, 선두 64B 폴링 | **900s 상한 도달** |

변형 셀 (결정 변수 분리):

| 셀 | 가설 | 결과 | 판정 |
|---|---|---|---|
| Z 동일 크기 덮어쓰기 | 크기 불변이면 감지 불가? | 1.66s | **기각** — mtime 으로 잡힘 |
| A mtime 30일/1시간 노화 | TTL 이 파일 나이 비례? | 29.07s / 29.11s | 나이 무관 **~29s 속성 캐시 상한** 존재 |
| T 단발 읽기 (T초 후 1회) | 폴링 자체가 치유 유발? | T=5·15·30·60·120 전부 stale | **채택** |
| F 열린 fd 재읽기 | open 재검증 우회? | 180s 상한 도달 | **채택** |
| W 4MB 전체 읽기 | 부분/전체 갈림? | 1.21s | **채택** — L(64B)과 정반대 |

"디렉터리 수 초, 내용 수 분"이라는 사전 관측의 실체: 능동 관찰자(폴링·전체읽기)는
1.2~29s 에 자가 치유되고, 실사용 패턴(단발·held-fd·부분읽기)은 무기한이다.

## 기전의 1차 증거

- **lease 는 깨지지 않는다**: 게스트 쓰기 직전 부여된 `LEASE(RH)` 가 쓰기 후에도
  `smbstatus --locks` 에 그대로. (l.bin: 11:41:59 부여 → 11:42:01 쓰기 → 수 분 유지)
- **치유의 주역은 kernel change notify**: `= no` 로 끄면 H 폴링이 fast/무기한 **교대**
  로 퇴화 (F-C-F-C-F, 5회). 복원하면 5/5 fast. 교대 자체의 원인은 미해명 — 마운트
  해제를 넘어 지속되는 상태가 세션 어딘가에 있다 (임시·운영 마운트가 SMB 세션을
  공유함을 `smbstatus` 로 확인 — 인증 세션 재사용, smbd 단일 PID).
- **notify 로도 안 잡히는 것**: T·F·L 무기한 셀은 notify 켜진 상태의 실측이다.

## 쌍안정 — 예정에 없던 발견

닫는 A-B-B-A 대조에서 기본 상태의 T·F 가 **fresh** 로 나왔다 (여는 대조에서는 stale).
이후 기본 상태에서 L 0.014s, lease 를 쥔 채 단발 60s 읽기도 fresh. 즉 **같은 설정·
같은 smbd 프로세스·같은 세션에서 병리 상태와 건강 상태가 모두 실측**됐다.

- 전환 시점 사이의 서버측 사건은 `smbcontrol all reload-config` 2회뿐 (인과 미확증).
- 건강 상태에서 held-fd 재읽기가 40ms 에 신선 → push 무효화가 작동 중.
- 병리 상태 재유발 시도: inotify 이벤트 폭풍 5만 건(큐 한계 16384 의 3배) → 실패
  (T+5s fresh). **큐 오버플로 단독 가설은 기각에 가깝다.**
- 웨지 트리거 미해명 — [open-questions.md](../open-questions.md) 에 재개 조건과 채집
  절차를 남겼다.

측정 방법론 소득: A-B-B-A 의 닫는 대조가 없었으면 "옵션이 고쳤다"로 오판했을 것이다.
실제로는 옵션 측정 전에 병리가 소멸해 있었다 — **옵션 실효의 실측은 건강 상태의 무회귀
확인으로 강등**되었고, 채택 논거는 기전 성질(캐시 부재 = stale 대상 부재)로 옮겼다.

## 비용 측정 (Q4)

실제 작업 4형, 3회 중앙값, base1↔base2 앵커 간 드리프트 없음:

| 작업 부하 | base | nodatacache | nomdatacache | 둘 다 |
|---|---|---|---|---|
| (a) 문서 20개 연속 읽기 | 0.087s | 0.089s | 0.093s | 0.091s |
| (b) git status+diff ×3 | 1.35s | 1.35s | 1.36s | 1.31s |
| (c) 트리 열거+읽기 17.8k | 6.64s | 6.62s | **28.5s** | 28.0s |
| (d) node_modules 22k 열거 | 62.7s | 62.6s | **154.8s** | 151.8s |

게이트: (a) ≤30%/+1s, (b) ≤50%/+3s, (c) ≤50%, (d) ≤100%/+20s — 측정 전 확정.
`nodatacache` 전 게이트 통과 (회귀 측정 불가 수준). `nomdatacache`·둘 다는 (c)(d) 기각.

## 서버측 kernel oplocks (Q5·Q6)

동일 path 의 격리 공유에 `kernel oplocks = yes` 하나만 다르게 두고 대조:

- 맥이 받은 lease: **`LEASE()` — 빈 lease** (운영 공유는 동시에 `LEASE(RH)` 정상 부여
  — (S) 파라미터의 공유별 격리 성립 확인).
- held-open 유지 중 `/proc/locks`: **커널 lease 0건.** F_SETLEASE 는 걸리지 않는다 —
  클라이언트에 캐싱 권리가 없으니 지킬 것도 없다.
- 게스트 로컬 `open()` 지연: 0.0ms ×5 — 우려했던 break 대기(`fs.lease-break-time`
  45s)는 깰 lease 가 없어 발생 자체가 없다.
- 일관성: T·F·L 전부 fresh (캐싱이 없으니 당연).

가설("커널 break 로 캐시를 켠 채 일관성")의 전제가 무너졌다: `man smb.conf` 의
`smb2 leases`/`kernel oplocks` 배타 관계가 실측으로 확인됐고, 실효는 **공유 전체의
캐싱 몰수**다. 같은 일관성을 `nodatacache` 가 클라이언트 단위·비용 0 으로 얻는다.

## 기타 확인

- `dir_cache_off`(nsmb.conf): macOS 26.6 매뉴얼에 부재. 문서화된 키는
  `dir_cache_min/max`, `max_dirs_cached`, `max_cached_per_dir` — 디렉터리 열거가 항상
  신선(D셀)해서 쓸 일이 없었다.
- `forcenewsession` 은 무인 마운트에서 인증 프롬프트 위험 — 기존 세션 재사용이 무인
  동작의 전제였다.
- 게스트 시계 step 잔재: journal 과 `ps lstart` 가 3시간 어긋난 것을 관측 (층 1 의
  흔적). 웨지 트리거 후보에 시계 step 이 있는 이유다.
